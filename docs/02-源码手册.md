## 0.5 `server/py-probe.js`（约 90 行）—— 为什么需要它

导入 XML 会 `spawn` 一个 Python 去跑 `tools/gen_tags.py`。Windows 上 `python` 这个名字有三种
「看着能用、其实不能用」的形态，其中最坑的是第三种：

| # | 形态 | `spawn` 表现 | 用户看到 |
|---|---|---|---|
| ① | 没装 Python | `ENOENT` 事件 | 至少是个明确的“找不到” |
| ② | 装了但没勾 Add to PATH | `ENOENT` 事件 | 同上 |
| ③ | 命中 `%LOCALAPPDATA%\Microsoft\WindowsApps\python.exe`（应用商店 0 字节占位别名，未安装真 Python） | 子进程**正常启动并立即退出**，`code = 9009`，stdout/stderr 全空 | **「gen_tags.py 退出码 9009」—— 看起来像脚本崩了** |

9009 是 Windows 的「命令未找到」。也就是说脚本**一行都没执行**，改 XML、改脚本都没用。
所以这里把「解释器是否可用」提前问清楚：

```
探测顺序：MYX_PYTHON  →  python  →  py -3  →  python3
每个候选：
  1. whichAll(cmd)              where / command -v 定位落点
  2. 落点只有 \WindowsApps\ → 直接判不可用，且【不去执行】
     （执行占位别名会弹出应用商店，体验更糟）
  3. spawnSync(cmd, ['-c','import sys;print(...)'])  真跑一句，确认是 Python 3.6+
结果缓存（PY_CACHE），一次进程生命周期只探测一次
```

| 名字 | 作用 |
|---|---|
| `probePython(force)` | 返回 `{ok:true, cmd, args, version, exe, tried}` 或 `{ok:false, tried, error}`；`force` 跳过缓存 |
| `PY_NEED` | 最低版本 `'3.6'`（`gen_tags.py` 用了 f-string） |
| `PY_HELP` | 多行中文处置说明，前端与日志原样展示（讲清 9009、三种成因、三种修法） |
| `whichAll(cmd)` | 跨平台“命令解析到哪些路径” |

调用点：`verify-server.js` 的 `/api/import`（探测失败即中止导入，不再 spawn）、
`GET /api/env`（前端页面打开即自检）、启动日志（导入能力一眼可见）。
`tried` 数组是给人看的证据链，例如：

```
["python：只有 Microsoft Store 占位别名（C:\Users\x\AppData\Local\Microsoft\WindowsApps\python.exe），未安装真 Python",
 "py：不存在", "python3：不存在"]
```

## 0.6 扫描耗时的两个乘数（改这里前必读）

`Runner.scanFull()` 的耗时不是「变量个数」决定的，而是：

```
耗时 ≈ 响应块数 × 单块往返
块数 = 每个读取列表的响应字节 ÷ 448（PLC 的通道块上限）
```

而 `CodesysV3Client.recvService()` 是**收一块 → 回 ACK → 再收下一块**的严格串行，
所以块数等于往返次数。这就是为什么：

- 230 个标量（46 个列表 × 1 块）→ 46~65 次往返，有线约 60ms
- **1 个** `ARRAY[0..7999] OF REAL`（32000B）→ 约 72 次往返，跨网段就是 580ms

> 能否省掉逐块 ACK？**不能**。实测把 ACK 改成只回最后一块，PLC 直接返回
> `通道错误 8400` 并把整次读取作废（tools 里留了这次实验的结论）。

**所以：完整读的耗时无法靠代码消除。** 代码只负责「如实测量 + 如实呈现 + 不遗漏任何一个符号」。

| 机制 | 位置 | 说明 |
|---|---|---|
| 完整登记 | `buildFullLists()` | 默认把**全部**标量与复合符号都登记进读取列表，一个不落 |
| 块数计量 | `c.lastBlocks`（`recvService()` 每收一块 +1）→ `stats.blocks` | 界面「扫描耗时」悬停显示「共 N 块 · 每块 X ms」，用于区分「块数多」与「单块慢」 |
| 真实刷新间隔 | `tick()` 里 `gap = now - lastTickAt` → `stats.gapMs` | 一轮读不完时实际间隔 = 目标周期 + 上轮耗时，如 580+500≈1.1s；界面据此标黄，不假装正常 |
| 空扫描心跳 | `tick()` 的 `else if (this.seq % 10 === 1)` | 边界情况仍发帧，避免「最近更新」停住像卡死 |
| 按需读（可选） | `loadAppData()` 的 `s.onDemand` + `arrayPage(key,page,size,fresh)` | **仅当** `MYX_BIG_SYM_BYTES>0` 时启用，把超阈值符号排除出轮询、点开时读一次（缓存 30s）。默认 0 = 不启用 |

配套探针 `tools/probe-latency.js`：测「单块往返基准」与「大块每块耗时」，
两者一比即可判定是链路问题（每块 4ms+）还是块数问题（每块正常但块数多）。
用例 `tests/test-big-sym.js` 锁住「默认每个符号都在周期扫描里」这条契约。
用例 `tests/test-big-sym.js` 锁住「标记 / 不扫 / 仍可读」三件事。

## 1. `server/codesys-v3-client.js`（535 行）

> 协议客户端。`require` 它即可在任意 Node 程序里读写 PLC，不需要 Web 层。

### 1.1 模块级

| 名字 | 作用 |
|---|---|
| `H(str)` | 十六进制字符串 → Buffer（自动去空格），写报文的唯一入口 |
| `u16le(v)` / `u32le(v)` | 小端整数 → Buffer |
| `crc32(buf)` | IEEE 802.3 反射实现；块校验 = `CRC32(整条服务载荷)` |
| `LOGIN_TAGS` | 60B 登录载荷常量块（用户名/密码空 + 32B 授权块） |
| `TAG_TYPES` | 示例 18 个变量的类型表（仅供自带 demo 用） |
| `decodeValue(key, buf)` | 快速解码（demo 用）；正式路径请用 `drill-core.decodeLeaf` |

### 1.2 构造与连接

```js
new CodesysV3Client(host, port = 11740, opts)
```

| 选项 | 默认 | 说明 |
|---|---|---|
| `allowWrite` | `false` | 写入总开关。**第一个闸门**。关闭时 `writeValue()` 直接抛错 |
| `flowControl` | `false` | 每块等 `0280` 回执再发下一块（多块传输时需要） |
| `maxFirst` / `maxCont` | 468 / 448 | 首块 / 续块服务载荷上限 |

构造函数还会算出 `senderAddr` / `receiverAddr`：取**与目标同网段**的本机 IPv4，
找不到就回退 `127.0.0.1`。多网卡机器这是关键——用错网卡会导致 PLC 收不到回包。

### 1.3 块驱动层

| 方法 | 职责 |
|---|---|
| `sendFrame(dgram)` | 拼 8B 帧头（magic + 总长）后写出 |
| `waitForFrame(timeoutMs)` | 从 `rxBuf` 切出完整帧，返回头之后的 dgram；超时抛「读帧超时」 |
| `sendService(svc)` | ≤468B 走单块；否则首块 + 续块；`flowControl` 时逐块等回执 |
| `waitChanAck(blkId)` | 等 `0280` 回执；`0300` 视为放行；`8400/8500` 返回 false；期间其他帧存入 `preBuffer` |
| `chanPrefix()` | 20B 通道前缀 |
| `chanBlk(svc)` | 组装单块（含 remaining + crc32） |
| `sendChanAck(blkId)` | 回 36B 的 `0280` 回执 |
| `recvService(timeoutMs)` | 收齐一条服务消息：跳控制包、回 ACK、按 remaining 拼接 |

> `preBuffer` 是必需的：等回执时可能先收到别的帧，不能丢，交给下一次 `recvService` 消费。

### 1.4 服务层

| 方法 | 职责 |
|---|---|
| `serviceMsg(grp, cmd, payload)` | 拼 20B 服务头 + 载荷 |
| `request(svc)` | 发送 + 收响应 + 校验「组\|0x80、命令号一致」，返回 `{ svc, payload }` |
| `parseTags(buf)` | 解析 `ID + 变长长度 + 值` 序列 → `[{id, value}]` |

### 1.5 握手七步

| 方法 | 返回 | 关键细节 |
|---|---|---|
| `connect()` | this | `net.connect`，可带 `MYX_SRC` 绑定源地址；`setNoDelay(true)` 关 Nagle |
| `nsQuery()` | 设备名 | 用**独立短连接**，`finally` 里必关——僵尸 socket 会占死 PLC 的唯一连接名额 |
| `nsQueryOnMain()` | true | 主连接首包必须是 NS 查询（seq=02），与厂商拓扑对齐 |
| `openChannel()` | chId | 响应里找 `8300`，chId 在 `i+14` |
| `sessionCreate()` | 响应字节数 | 01/01，空载荷 |
| `login()` | sessionId | 01/02；从响应 `21 84 80 00` 处读 u32 |
| `getRoot()` | 根句柄 | 09/07；同时捕获 `3a 84 80 00` 后的**设备令牌** |

### 1.6 读取

| 方法 | 职责 |
|---|---|
| `buildNameListPayload(names)` | 组装登记载荷：`13`(固定) + `3A`(设备令牌) + `18`(条目数) + 条目序列。**令牌为空直接抛错**，不允许用 0 代替 |
| `prepareRead(names)` | 09/01 登记，从响应 `10 84 80 00` 处取列表句柄 |
| `executeRead()` | 09/03，请求只有 8B；按 `(w1-0x80)+((w2-0x80)<<7)` 解析值域长度，返回 `Buffer[]`（与登记顺序一致） |

### 1.7 写入

| 方法 | 职责 |
|---|---|
| `encodeWriteTags(name, data)` | 组装 `13`(标志全 0) + `21`(名字4对齐) + `1E`(12B 值缓冲) |
| `writeValue(name, data)` | 09/04 单发；解析响应 `0x20` 状态码，返回 `{ ok, status, raw }` |
| `writeValues(items)` | 串行批量（PLC 单连接，不能并发） |

### 1.8 直接运行

`node server/codesys-v3-client.js <ip>` → 走完 7 步后读示例 18 点 6 轮。用于确认协议层本身是否通。

## 2. `server/drill-core.js`（310 行）

> 纯函数模块：不碰网络、无副作用，可离线单测（`tests/test-union-learn.js` 就是它的单测）。

### 2.1 类型导航

| 函数 | 输入 → 输出 | 说明 |
|---|---|---|
| `init(types)` | 类型库对象 | 注入 `gen/<APP>.types.json` 的 `types`；同时建 IEC 名 → 类型名索引 |
| `xmlTypeName(iecType)` | `"ARRAY [0..10] OF ST_AXIS_CONTROL"` → `"T_ARRAY__0__10__OF_ST_AXIS_CONTROL"` | 把 IEC 文本类型映射到 XML 类型定义名（两通道：数组构造命名 / iecname 索引） |
| `typeDef(name)` | 类型对象 / undefined | 按名或 IEC 名查定义 |
| `typeSize(name)` | 字节数 / 0 | 只看 XML 声明的 size |
| `infSize(name)` | 字节数 | size 为 0（UNION）时递归取成员最大值 |
| `taintedType(name)` | bool | 布局是否可疑：size=0 / 成员偏移缺失 / 递归污染 |

### 2.2 结构展开

```js
expandTree(prefix, typeName, writable, depth, counter, off, taint)
```

递归产出层级树，节点两种：

- **叶子**：`{ path, type, leaf:true, off, size, flags }`（`off` = 在整符号 blob 内的推算偏移）
- **中间层**：`{ path, type, children[], off, size, stride?, tainted? }`

关键点：

- **数组步长 = 数组总字节 ÷ 元素数**（CODESYS 按对齐补位，元素类型自身尺寸不对）。
  例：261B 元素 → 实际占 264B。
- **UNION**：所有成员叠在偏移 0，`counter.learn = true`（要求走对账流程）。
- **成员偏移与前方冲突**：按 IEC 规则顺延，并从该成员起全部标记可疑。
- `DRILL_ARR`（16）限制单维展开的元素数；`DRILL_MAX`（4096）限制总节点数。

> `counter.learn` 是「这棵树不能盲信」的总开关：只要有一个节点可疑就置位，
> 上层据此决定走「整读解码」还是「先对账再解码」。

### 2.3 树 → 行 / 解码 / 编码

| 函数 | 说明 |
|---|---|
| `flattenTree(tree)` | 扁平成表格行，每行带 `depth` / `anc`（祖先链，前端据此折叠） |
| `readBase(base, buf, off)` | 按 IEC 基础类型读一个数（BOOL/INT/DINT/REAL/LREAL/…） |
| `decodeLeaf(leaf, buf)` | 叶子解码：字符串截断、枚举附字面量名、数值按类型宽度 |
| `encodeLeaf(type, value)` | 叶子编码：按 XML 类型宽度精确编码（BOOL 只 1 字节） |
| `packPaths(paths)` | 登记名按 **460B 预算**分批（超 1 块会触发 PLC 缓冲配额错误） |

### 2.4 UNION 布局对账

```js
learnUnionLayout(sym, leaves, readMap, blob)
// → { ok, blobBytes, stride, off:{path→绝对偏移}, weak[], famCount, reason? }
```

算法（实现见函数注释）：

1. 顶层是数组 → `stride = blob.length / 元素数`；不整除直接失败
2. `readMap`（逐名读结果）解码后作为**基准真值**
3. 按「成员族」（把 `[0] [1] [2]` 归一成 `[*]`）分组
4. 可疑成员按类型对齐枚举候选偏移（IEC 推算位优先），要求该族**所有元素**都与基准一致
5. 多解（值恒同）→ 取首个并记入 `weak[]`（弱验证）
6. 任一成员族无解 → 整体失败（宁可回退逐名读，不可出错值）

## 3. `server/verify-server.js`（约 1660 行）

### 3.4 成员树（写入弹窗的折叠数据源）

### 3.5 Runner（单连接状态机）

PLC 只接受一条 TCP 连接，所以全部操作串行化。

| 成员 | 职责 |
|---|---|
| `q(fn)` | 串行队列：所有读写都排进这里，保证不并发 |

| `refreshWatch(keys)` | 只对**新增**的监控名分批登记（不重读全部） |
| `scanWatch(c)` | 读监控列表并广播 `wvals` |
| `scanFull(c)` | 遍历全量批次并广播 `full` |
| `pushReadWin(ok)` | 维护「最近 80 次读」窗口（成功率按此算，不用累计值） |
| `scheduleReconnect(ms)` | 唯一重连排期：多个失败源同时触发也只排一次 |
| `arrayPage(key, page, size)` | 大数组分页取值：从 `arrayRaw` 缓存解码一页元素，翻页不额外读 PLC |
| `switchApp(app)` | 换程序：重载数据 → 断旧连接 → 作废旧回调 → 重连 |

| `drill(key)` | 钻取：展开成员树 + 取值（整读优先，可疑布局走对账） |
| `drillWrite(key, value)` | 成员写：按成员名单独写（不走整块） |
| `writeTest(key, mode, value)` | 写入验证：no-op 回写 / 设定值，写前读原值、写后回读校验 |
| `snap()` / `emitState()` / `note()` | 状态快照、状态跃迁广播、事件留痕 |

| `/api/import` | POST | 上传 XML → 生成数据 → 热切换 |
| `/api/select` | POST | 切换程序 |
| `/api/delete` | POST | 删除程序及其全部产物 |

**POST 路由必须显式登记**：`http.createServer` 里有个 POST 白名单，未登记的路径会落到静态文件分支。
新增 POST 接口时务必加进那个判断（`p === '/api/xxx'`）。

### 3.7 WebSocket

上行（浏览器 → 服务端）：

| `cmd` | 参数 | 作用 |
|---|---|---|
| `connect` / `disconnect` | — | 手动连 / 断 |
| `period` | `ms` | 改周期（100..5000） |
| `watchSet` | `keys[]` | 设置监控列表 |
| `drill` | `key` | 取成员树 + 值 |
| `drillWrite` | `key`, `value` | 写成员 |
| `writeTest` | `key`, `mode`, `value` | 写入验证（`mode: 'noop' \| 'set'`） |
| `resetStats` | — | 清统计与窗口 |

下行（服务端 → 浏览器）：

| `t` | 内容 |
|---|---|
| `state` | 状态快照（含握手进度、统计、事件、`readWin`） |
| `values` | 周期读结果（主点表） |
| `full` | 全量扫描结果 |
| `wvals` | 监控列表实时值（带 `ty` 类型） |
| `wtest` / `wprev` / `wcur` | 写入过程 / 写前值 / 写后值 |
| `drill` / `drillw` | 钻取树 / 成员写结果 |
| `rtt` | 单次 RTT + 统计 + 窗口 |
| `log` | 报文流水 |
| `app` / `plccfg` / `period` | 程序切换 / 地址变更 / 周期变更 |

### 3.8 退出

`shutdown(sig)` 注册了 `SIGINT/SIGTERM/SIGBREAK/SIGHUP`：
先 `sock.end()` 发 FIN，150ms 后 destroy 再退出。
**必须优雅退出**——被强杀的进程会留下占位的 socket，让下一次握手超时。

## 5. `tools/gen_tags.py`（约 490 行）

```
XML ─┬─ Header/ProjectInfo → 程序名
     ├─ TypeList          → 类型库（成员/偏移/数组维度/枚举）
     └─ NodeList          → 符号清单
                ↓
     选点（profile 优先，否则内置模板，再不匹配则自动选 32 个标量）
                ↓
     server/gen/<APP>.tags.json / .symbols.json / .types.json
     out/<APP>/tag_table.json …    （调用 codesys_symconfig.py）
     server/profiles/<APP>.profile.json
     firmware/gen/hmi_tags_<APP>.{c,h}   （仅当存在 firmware/ 目录）
```

**硬规则**：所有变量类型以 XML 为唯一准则，生成器只做搬运，不做任何类型推断。

| 函数 | 职责 |
|---|---|
| `parse_xml(path)` | XML → `(程序名, 类型表, 符号表)`；去命名空间前缀 |
| `select_points(app, symbols, profile)` | 选点：档案优先 → 内置模板 → 自动选点 |
| `auto_select_points(symbols)` | 外来程序兜底：全部标量按名排序取前 32 个 |
| `gen_for_xml(path, check_only)` | 单个 XML 的完整生成流程 |
| `list_apps()` | 列出已导入程序（`--list`） |

## 6. `tools/codesys_symconfig.py`（约 570 行）

> XML → 全量表 + 布局头文件 + 审计报告。独立于 Node 层，可单独跑。

| 产出 | 内容 |
|---|---|
| `tag_table.json` | 符号清单 + 类型字典 + 偏移/跨度/访问权限/置信度（全量页与批量登记的数据源） |
| `symbols.csv` | 符号级清单（给人核对） |
| `leaf_vars.csv` | 叶子级变量表（每个可寻址成员的相对偏移） |
| `types_layout.h` | 结构体大小/对齐/成员偏移宏（不依赖编译器布局） |
| `types_layout.json` | 同上，机读 |
| `audit.md` | 审计报告：权限越界、布局不可信、FB 实例、命名问题 |

布局按 CODESYS 实际规则计算（成员对齐 + 尾部补齐），并用数组跨度做交叉校验；
校验不过的类型标 `unverified`，**不假装可信**。
