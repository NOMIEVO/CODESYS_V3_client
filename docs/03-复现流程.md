# 03 · 复现流程

从一台干净机器开始，到「看见 PLC 数据在浏览器里跳」。每一步都给出**预期输出**，
对不上就停下查该步的「不符怎么办」。

两种复现路径：

- **A. 有 PLC**：完整链路（读 + 写 + 结构体钻取）
- **B. 没有 PLC**：仍能跑通除实时值以外的全部环节（离线验证包完整性）

---

## 0. 环境检查

最快一步：双击 **`0-check-env.bat`**，它会检查 Node / 依赖 `ws` / Python 三项并给出处置办法。
想手工核对就执行：

```bash
node -v                          # 要 v18 或更高
python -V                        # 要 3.6 或更高（导入 XML / 生成点表时需要）
python -c "import sys;print(sys.version_info[:2])"   # 能打印 (3, 8) 这类元组才算真能跑
```

**预期**

```
v22.22.2
Python 3.13.14
(3, 13)
```

**不符怎么办**

| 现象 | 处理 |
|---|---|
| `node` 不是内部或外部命令 | 装 Node.js 18+，装完重开终端 |
| `python` 不是内部或外部命令 | 装 Python 3.8+，安装时勾选 *Add python.exe to PATH* |
| 敲 `python` 弹出**应用商店**，导入报 **退出码 9009** | 命中了 `%LOCALAPPDATA%\Microsoft\WindowsApps\python.exe` 占位别名，等于没装：按上一行安装真 Python，或设 `MYX_PYTHON=<python.exe 全路径>` |
| `python` 能跑但版本 < 3.6 | `gen_tags.py` 用了 f-string，装 3.8+ |

> **9009 的含义**：Windows 的「命令未找到」。它说明 `gen_tags.py` 一行都没执行，
> 所以**不要**去改 XML 或脚本——问题在解释器本身。
> 这个坑在不同机器上表现不同（有的机器 PATH 里有真 Python 就一切正常），
> 是「我这边好、别人导入就失败」最常见的原因。

## 4. 打开界面

浏览器访问 <http://127.0.0.1:8095>。

### 4.1 有 PLC 时

自动连接，7 步握手逐项点亮：

```
① NS 查询        12ms   设备名发现
② 主连接 NS       8ms   seq=02 拓扑对齐
③ 开通道          6ms   chId 分配
④ 会话创建        5ms   service 01/01
⑤ 登录            7ms   session_id 下发
⑥ GetRoot         9ms   根句柄 + 设备令牌
⑦ PrepareRead    11ms   名单登记
```

随即可见：

- 顶栏状态转绿（`在线`），端点显示 `● 192.168.1.92:11740`
- RTT 曲线开始描绘（默认 500 ms 一次）
- 「读成功率」显示 `100.0%`（按最近 80 次算）
- 中间列点表卡片的值开始跳动
- 底部控制台滚动 `→ 09/03 ExecuteRead` / `← 09/03 响应 #N 21 条目 RTT 9ms`

### 4.2 没有 PLC 时（离线复现）

程序照常启动，链路显示红色与失败原因：

```
状态: 握手失败
顶栏横幅: 11:04:06 握手失败 · 目标不可达（IP 或网段不通）
```

离线仍可验证的功能：

| 功能 | 离线表现 |
|---|---|
| 符号表浏览（全量变量页） | ✅ 全部符号列出，值显示 `--` |
| 结构体成员树（选择变量 → 展开） | ✅ 完整层级（数据来自类型库，不需 PLC） |
| 变量路径解析 / 类型显示 | ✅ 正常 |
| PLC 地址配置 | ✅ 可改、可保存、会重连 |
| 实时值 / 写入 / 钻取取值 | ✗ 需 PLC |

**离线复现建议**：把地址填成一个不存在的 IP（如 `192.168.1.250`），就能稳定复现「握手失败」状态与离线可用功能。

## 5. 改 PLC 地址（第一次必做）

点顶栏那串 `● 192.168.1.92:11740` → 弹「PLC 配置」：

```
  IP 地址   [192.168.1.92          ]
  端口      [11740                 ]
  当前配置来自 plc-config.json（界面保存过）

  [恢复默认]              [取消] [保存并重连]
```

填自己的地址 → 点「保存并重连」。

**预期**

1. 提示 `✓ 已保存，正在用新地址重新握手…`，约 1 秒后弹窗自动关闭
2. 顶栏端点变为新地址，状态短暂变红后转绿（地址通的话）
3. `server/plc-config.json` 生成：

```json
{
  "host": "192.168.1.92",
  "port": 11740,
  "savedAt": "2026-11-12T03:43:48.578Z"
}
```

**故意填错会怎样**（这一步能验证校验生效）

| 输入 | 预期提示 |
|---|---|
| `999.1.1.1` | ✗ IP 格式不正确（例：192.168.1.92，每段 0..255） |
| `192.168.1` | ✗ IP 格式不正确（例：192.168.1.92，每段 0..255） |
| `192.168.1.a` | ✗ IP 格式不正确（例：192.168.1.92，每段 0..255） |
| 端口 `70000` | ✗ 端口须为 1..65535 的整数 |
| 正确地址 + 错误端口（如 `11741`） | 保存成功，但状态变红：`应答超时…`；改回 `11740` 后自动恢复在线 |

### 5.x 大数组分页浏览

全量变量页里，**元素是标量**的数组行右侧有「分页」按钮（`ARRAY [0..1999] OF REAL` 这类）：

```
1. 打开 /full → 找到数组行 → 点「分页」
2. 弹窗里一页 20 个元素，◀ / ▶ 翻页，或直接把页码填进输入框回车
3. 每个元素都能单独写：BOOL 选 0/1，数值填数字后点「写入」（或回车）
4. 点「当前值」单元格可一键带入写入框
```

预期：`ARRAY [0..1999] OF REAL` → 共 100 页；`ARRAY [0..500] OF BOOL` → 共 26 页。
数值随链路自动刷新（面板底部有提示），写入后立即回读。

> 元素是结构体的数组（`ARRAY[0..7] OF ST_XXX`）没有「分页」，走「展开」成员树。

### 7.x 导入旧编译器导出的 XML（SP17 及更早）

老版本 CODESYS 导出的符号配置常常**一个标量都没有**，整个程序只有一块连续通讯数组，例如：

```xml
<TypeArray name="T_ARRAY__0__1999__OF_REAL" iecname="ARRAY [0..1999] OF REAL" basetype="T_REAL">
  <ArrayDim minrange="0" maxrange="1999" />
</TypeArray>
<Node name="CommValue" type="T_ARRAY__0__1999__OF_REAL" access="ReadWrite" />
```

这类文件可直接导入，不必先改 XML：

| 行为 | 说明 |
|---|---|
| 自动选点 | 标量不足 8 个时按数组元素补点（`GVL.CommValue[0]`…`[7]`），保证控制台能起 |
| 程序名 | 中文名自动转 ASCII ID（保留 ASCII 部分 + 6 位哈希，如 `MyMachine_3f9a2c`），界面仍显示原名 |
| 点表 | 数组元素在 PLC 侧按元素名寻址，与标量同一条读取路径 |
| 全量页 | 数组本体整体显示（`8000B · 0000…`），不逐个列出 2000 个元素 |

**预期输出**

```
■ <程序原名>  ← Test\<程序原名>.Device.Application.xml
  App ID: <ASCII 部分>_<6 位哈希>（原名含非 ASCII，已转写；界面仍显示原名）
  符号总数（含容器/数组元素展开）: 2，类型数: 2
  [!] 与内置模板（DEMO_MACHINE）完全不匹配——外来程序，自动选点（可后续在 profile 微调）
  点表选择: 8 点（来源: 内置模板）
  [v] server\gen\<程序ID>.tags.json（8 点）
  ...
[OK] 生成完毕
APP=<程序ID>
```

想换点：改 `server/profiles/<程序ID>.profile.json` 里的 `key`（可写 `GVL.CommValue[100]` 这类元素），再跑一次生成。

## 8. 换一套 PLC 程序（完整换型流程）

```bash
# ① 把新程序的符号配置 XML 放进 example/（或 Test/）
cp 新程序.Device.Application.xml example/

# ② 生成
python tools/gen_tags.py --all

# ③ 启动并指定程序（多套并存时）
set MYX_APP=新程序名
node server/verify-server.js
```

**预期**：第 2 节的输出换成新程序名，点数按新程序的内置模板命中数决定。
若新程序与内置模板完全不匹配，会看到：

```
⚠ 与内置模板（SJJC/TBJ）完全不匹配——外来程序，自动选点（可后续在 profile 微调）
点表选择: 32 点（来源: 内置模板）
```

此时把所有标量按名排序取前 32 个，可编辑 `server/profiles/<新程序>.profile.json` 再重跑第 ② 步以精确选点。

**不重启进程也能换**：界面中列「程序」列表点选即可热切换（生成的数据必须已存在）。

## 9. 验证结构体钻取（需要 PLC）

1. 首页 →「选择变量…」
2. 搜索 `aAxisCtl` → 点「展开」→ 点某个 `aAxisCtl[n]` 的「展开成员」
3. 看到分组树：

```
▾ aAxisCtl[3]                [结构体]  收起
    fSetPosition                REAL
    fActPosition                REAL
  ▸ tState        [子结构] ST_AXIS_STATE · 9 项     展开
  ▸ aAbsSel       [子数组] ARRAY[0..2] · 3 项       展开
    bEnable                     BOOL
    bEnabled                    BOOL
    bLimitPos                   BOOL
    …
```

> 这份树是示例工程 `DEMO_MACHINE` 的实际结构（12 个成员，其中 1 个嵌套结构体、1 个数组）。
> 换成自己的工程后，这里会显示你自己类型的成员。

4. 点 `tState` 展开 → 看到 `bValid` / `bBusy` / `bError` … 逐个有实时值
5. 点任一成员行 → 自动加入监控列表，右侧写入面板出现该成员
6. 点「写入并回读」→ 打印五段式结果（读原值 → 写入 → 状态码 → 回读校验 → 结论）

**关键观察点**：根节点（`aAxisCtl[3]`）展开后是 12 行（含 2 个折叠组），
而不是把 `tState` 的 9 个成员、`aAbsSel` 的 3 个元素全部平铺出来。

## 9.5 排查「扫描耗时特别长」（数据量不大但很慢）

这是现场最常见的一类问题，而且**换一台电脑就复现不了**，因为它取决于链路而不是代码。

### 先看耗时的构成

```
扫描耗时 ≈ 响应块数 × 单块往返        块数 = 数据量 ÷ 448B
```

PLC 把响应按 ≤448B 一块切分，客户端**每块都要单独 ACK**（实测不可省，否则通道错误 8400）。
所以：

| 数据 | 块数 | 有线 0.8ms/块 | Wi-Fi 8ms/块 |
|---|---|---|---|
| 230 个标量（25KB，46 个列表） | ~65 | 约 60ms | 约 520ms |
| 1 个 `ARRAY[0..7999] OF REAL`（32KB） | ~72 | 约 58ms | 约 580ms |

**注意第二种**：全量页「变量」只有 1 个，但「数据量」31.3KB —— 慢的根源是字节数，不是变量个数。

### 一条命令定位

```bash
node tools/probe-latency.js
```

**预期（正常链路）**

```
① 单块往返基准（GVL.CommValue[0]，8B 量级，15 次）
   min 1ms · 中位 2ms · max 13ms · 抖动 12ms
② 大块整读（…，约 31.3KB）
   载荷 32000B → 块数 72（58ms / 60ms / 59ms）
   每块 0.81ms（基准 2ms/块，0.4 倍）
③ 判定
   ✓ 每块耗时 ≈ 标量往返 → 通讯正常，慢就是「块数多」的算术结果。
```

**异常（跨网段 / Wi-Fi）**

```
① 单块往返基准   中位 8ms · 抖动 40ms
② 每块 8.05ms（基准 8ms/块，1.0 倍）
   ⚠ 这条链路的单块往返偏高，这正是「数据量不大但扫描很慢」的直接原因。
```

**不符怎么办**

| 现象 | 处理 |
|---|---|
| 单块往返 4ms+ | 换网线直连 PLC / 同一交换机；关掉 VPN 与代理 |
| 多网卡机器（有线+无线都在） | `set MYX_SRC=<有线网卡IP>` 强制走有线 |
| 抖动 30ms+ | 网卡属性里关「节能 / 绿色以太网 / 中断节流」，退出抓包类软件 |
| 单块正常但块数太多 | 把不需要监视的大数组从 CODESYS 符号配置里去掉 |

### 本版的行为：完整读（默认）

**全部符号都参与周期扫描**，包括 32KB 的大数组和结构体数组。不会为了提速把任何变量排除在刷新之外。

- 顶部「扫描耗时」悬停显示「共 N 块 · 每块 X ms · 实际刷新间隔 / 目标周期」，
  用于判断慢在链路（每块 4ms+）还是块数（每块正常但块数多）
- 若一轮读不完，实际刷新间隔会自然大于目标周期（例如 580ms 扫描 + 500ms 间隔 ≈ 1.1s 一帧），
  这是完整读的必然结果，**不会丢数据**，指标会如实标黄提示

### 唯一会牺牲完整性的开关（不建议用）

`MYX_BIG_SYM_BYTES` 默认 `0`。显式设成非 0（如 4096）时，超过该字节数的复合符号
**不进周期扫描**，全量页那一行的「值」列会显示 **按需**（虚线下划线），
点「分页 / 展开」时才读一次并缓存 30s。

> 仅在「链路实在无法改善、又只看少数变量」时临时使用。
> 它会让那些行不再自动刷新——这与「全量页必须完整刷新」的要求相冲突。
