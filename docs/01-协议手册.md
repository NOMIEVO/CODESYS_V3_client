# 01 · CODESYS V3 协议手册

面向要**自己实现或改造**这套客户端的人。只讲：报文长什么样、字段什么含义、发出去会得到什么。

---

## 1. 分层

```
┌─────────────────────────────────────────┐
│ 服务层 service   业务命令（读/写/浏览）  │  20B 头 + 载荷
├─────────────────────────────────────────┤
│ 通道层 channel   分块、流控、CRC        │  通道头 + 服务层字节
├─────────────────────────────────────────┤
│ 帧层 frame       长度分界（TCP 流）    │  8B 头
├─────────────────────────────────────────┤
│ TCP 11740                            │
└─────────────────────────────────────────┘
```

TCP 是字节流，靠**帧头里的长度**切包；帧内可能装不下一条服务消息，靠**通道层**分块。

---

## 2. 帧层

| 偏移 | 长度 | 内容         | 取值                              |
| -- | -- | ---------- | ------------------------------- |
| 0  | 4  | magic      | `00 01 17 E8`（小端写 `0xE8170100`） |
| 4  | 4  | 总长度 u32 LE | `8 + 通道层字节数`                    |

发送：`sendFrame(dgram)` 拼 8B 头 + dgram。  
接收：`waitForFrame()` 先读 8B 头，再按总长度收满，返回头之后的 dgram。

**帧上限 516 字节**（含 8B 帧头）→ 通道层最多 508 字节。

---

## 3. 通道层

### 3.1 通道前缀（20 字节，每个包都有）

| 长度 | 内容                         | 示例                     |
| -- | -------------------------- | ---------------------- |
| 5  | 固定 `C5 6B 40 40 00`        | —                      |
| 7  | 发送者地址：`43 2D DC` + 本机 IPv4 | `43 2d dc c0 a8 01 24` |
| 6  | 接收者地址：`00 00` + 目标 IPv4    | `00 00 c0 a8 01 5c`    |
| 2  | 固定 `02 F1`                 | —                      |

> 本机 IP 取与目标同网段的那块网卡；找不到则回退 `127.0.0.1`。  
> 多网卡机器上可用 `MYX_SRC` 强制指定源地址。

### 3.2 首块（含服务消息的开头）

```
前缀(20) │ 01 81 │ chId(2) │ blkId(4) │ ackId(4) │ remaining(4) │ crc32(4) │ 服务字节
           包类型
```

| 字段          | 含义                              |
| ----------- | ------------------------------- |
| 包类型 `0181`  | 数据块（携带服务消息起点）                   |
| `chId`      | 通道号，开通道时分配                      |
| `blkId`     | 块序号，本端自增                        |
| `ackId`     | 已确认的对端块号                        |
| `remaining` | **整条服务消息**的字节数                  |
| `crc32`     | `CRC32(整条服务消息)`，IEEE 802.3 反射实现 |

首块服务字节上限 **468**（516 − 8 帧头 − 40 通道头）。

### 3.3 续块

```
前缀(20) │ 01 80 │ chId(2) │ blkId(4) │ ackId(4) │ 服务字节
```

无 `remaining` / `crc32`。服务字节上限 **448**（实现取保守值，保持 4 字节对齐）。

### 3.4 通道回执与错误

| 包类型               | 含义                 | 处理                  |
| ----------------- | ------------------ | ------------------- |
| `02 80`           | 数据块回执（含被确认的 blkId） | 记录 ackId；流控时用于放行下一块 |
| `03 xx`           | 通道层可继续发下一块         | 视作放行                |
| `84 00` / `85 00` | 通道错误               | 抛异常，附原始报文前 120 字节   |

接收侧每收到一个数据块都要回 `0280` 回执（36 字节：前缀 + `0280` + chId + blkId）。

### 3.5 组包与拆包的完整规则

**发送**

```
服务消息 ≤ 468B  → 单块（01 81）直接发，PLC 直接回服务响应
服务消息 > 468B  → 首块 01 81 + 续块 01 80 …
                   可选：每块后等 0280 回执再发（flowControl）
```

**接收**

```
首块 01 01 / 01 81 → ackId = blkId；回 0280；读 remaining 与服务字节
                     够长 → 直接返回；不够 → 缓存，继续收续块
续块 01 00 / 01 80 → ackId = blkId；回 0280；拼接，够了就返回
其余（0280 等控制包）→ 跳过
```

## 4. 服务层

### 4.1 消息头（20 字节）

| 偏移 | 长度 | 字段               | 说明            |
| -- | -- | ---------------- | ------------- |
| 0  | 4  | magic            | `55 CD 10 00` |
| 4  | 1  | 组 grp            | 见下表           |
| 5  | 1  | 保留               | —             |
| 6  | 2  | 命令 cmd u16 LE    | 见下表           |
| 8  | 4  | sessionId u32 LE | 登录前为 0        |
| 12 | 4  | 载荷长度 u32 LE      | —             |
| 16 | 4  | corr u32 LE      | 通常 0          |
| 20 | n  | 载荷               | —             |

> 实现里组与命令按 u16 依次写入（`u16le(grp)`, `u16le(cmd)`），高位补 0，  
> 效果等同「1 字节组 + 1 字节保留 + 2 字节命令」。

### 4.2 命令总表

| 组  | 命令 | 用途                | 载荷                    | 响应关键 tag                   |
| -- | -- | ----------------- | --------------------- | -------------------------- |
| 01 | 01 | 会话创建              | 空                     | —                          |
| 01 | 02 | 登录                | 60B（见 4.3）            | `0x21` → session_id        |
| 09 | 07 | GetRoot           | 空                     | `0x38` → 根句柄；`0x3a` → 设备令牌 |
| 09 | 01 | PrepareRead（按名登记） | 名单（见 4.4）             | `0x10` → 列表句柄              |
| 09 | 03 | ExecuteRead       | 8B：`10 84 80 00` + 句柄 | `0x1d` 值条目序列               |
| 09 | 04 | WriteValue（单发写）   | 三标签（见 4.6）            | `0x20` → 状态码               |
| 09 | 08 | 按父句柄 + 名浏览        | —                     | —                          |
| 09 | 09 | 按句柄查节点            | —                     | —                          |

|                       |                                     |
| --------------------- | ----------------------------------- |
| **响应校验**：\`响应组 == 请求组 | 0x80\` 且命令号一致，否则视为错包并抛异常（附前 20 字节）。 |

### 4.3 登录载荷（60 字节）

```
22 84 80 00  01 00 00 00        ← tag 0x22 用户名（空串）
23 84 80 00  CD 0F DA 5E        ← tag 0x23 密码（空）
81 01 A8 00  10 02 00 00        ← 父标签（授权块组）
11 A0 80 00                     ← tag 0x11，长度 32
<32 字节授权块>
```

授权块在当前运行时上是跨会话常量，直接复刻即可；响应里 `21 84 80 00` 后 4 字节为 `session_id`。

### 4.4 按名登记的载荷

```
13 84 80 00  48 00 01 00                ← tag 0x13，值 0x00010048（固定）
3A 84 80 00  <deviceToken u32>          ← tag 0x3A，GetRoot 下发的设备令牌
18 84 80 00  <条目数 u32>                ← tag 0x18
<条目 1><条目 2>…
```

**条目编码**

```
19 │ (T-2) │ 名长u16 │ "Application.xxx" │ 00 │ 补零
     ↑ T = align4(名长含\0 + 4)
```

例：名 `Application.GVL_MAIN.diTotalCount`（26 字符 + `\0` = 27B）→ `T = align4(27+4) = 32`，补 5 个零字节。

**两条硬约束**

1. **设备令牌必须原样带回**。GetRoot 响应的 `0x3a` 就是它；用 0 代替会被 PLC 拒绝（错误 `14 02 02 09`）。
2. **单条登记载荷 ≤ 460 字节**。超了会跨块，触发 PLC 缓冲配额错误。所以大批量要**分批登记**  
   （`drill-core.js` 的 `packPaths()` 就是干这个：24B 头 + 逐条累加到 460B 封顶）。

### 4.5 ExecuteRead 请求与响应

**请求**（8 字节）：`10 84 80 00` + 列表句柄 u32 —— 不带任何名字，读的是登记时的整张名单。

**响应**：头部 tag 之后是一串值条目：

```
条目：1D │ w1 │ w2 │ 00 │ 保留(4B) │ 值
       标签
值域字节数 = (w1 − 0x80) + ((w2 − 0x80) << 7)      ← 含 4B 保留，4 字节对齐
条目步进   = 4 + 值域
```

**值域编码示例**

| 值域字节数 | w1 w2   | 含义           |
| ----- | ------- | ------------ |
| 8     | `88 80` | 4B 值 + 4B 保留 |
| 24    | `9C 80` | 20B 值        |
| 96    | `E4 80` | 92B 元素       |
| 1056  | `A4 88` | 1052B 数组     |
| 6232  | `DC B0` | 6228B 结构体数组  |

单条上限 `0x7F + 0x7F<<7 = 16383` 字节。

**值解码顺序**：按登记顺序，`bufs[i]` 对应第 i 个名字；解码宽度由 XML 类型决定（见第 6 节）。

### 4.6 写入（09/04）

**没有 PrepareWrite**，一条请求完成写入。载荷是三个标签：

```
13 │ 04 │ 00 00 00 00                       ← 标志（注意：读是 48 00 01 00，写是全 0）
21 │ <变长长度> │ "Application.xxx\0" + 补零  ← 变量名（4 字节对齐）
1E │ 12 │ <len u16><0000><值 8 字节>        ← 值：定长 12B 缓冲，短值补零
```

**响应**：`20 02 00 00` = tag `0x20`、长度 2、状态 `0x0000` **成功**。

**注意事项**

- `BOOL` 必须写 **1 字节**；给 4 字节会被 PLC 以 `0x0F` 拒绝
- 写入是单条请求，批量写要串行发多条（本实现 `writeValues()` 即串行）
- 写入成功 ≠ 值会保持：写 PLC 输入映射点时，扫描周期会立即用实际输入覆盖

### 4.7 标签编码通则

```
ID（1 字节） │ 长度（变长） │ 值（长度字节）
```

长度是 7-bit 变长：每字节低 7 位有效，最高位 `0x80` 表示还有后续。  
小长度可单字节（`04`），实现里也大量出现三字节固定写法（`84 80 00` = 4）。  
解析时统一按变长处理即可。

## 5. 交互时序（完整一次）

```
Client                                  PLC
  │  ── NS 查询（短连接 1，seq 01）──────→  │
  │  ←─ 设备名（含 UTF-16 字符串）───────  │
  │  ── 关闭短连接 ──                     │   ← 必须关，PLC 只接受一条连接
  │                                       │
  │  ═══ 主连接 ═══                       │
  │  ── NS 查询（seq 02）──────────────→  │
  │  ←─ 221B NS 响应 ──────────────────   │
  │  ── 开通道 ───────────────────────→   │
  │  ←─ 含 8300，chId 在其中 ───────────  │
  │  ── 01/01 会话创建 ───────────────→   │
  │  ←─ 确认 ──────────────────────────   │
  │  ── 01/02 登录（60B）─────────────→   │
  │  ←─ 21 84 80 00 + session_id ───────  │
  │  ── 09/07 GetRoot ────────────────→   │
  │  ←─ 38（根句柄） + 3A（设备令牌）─────  │
  │  ── 09/01 PrepareRead（≤460B/批）──→  │
  │  ←─ 10 84 80 00 + 列表句柄 ─────────  │
  │                                       │
  │  ┌ 周期循环（默认 500ms）              │
  │  ── 09/03 ExecuteRead（8B）────────→  │
  │  ←─ 1D 值条目 × N ──────────────────  │
  │  └                                     │
  │                                       │
  │  ── 09/04 WriteValue（按需）───────→  │
  │  ←─ 20 02 00 00（状态 0 = 成功）────   │
```

## 6. 值解码规则

值本身是**原始字节**，语义由 XML 类型决定（客户端不猜类型）。

| IEC 类型                      | 字节   | 解码                      |
| --------------------------- | ---- | ----------------------- |
| BOOL                        | 1    | 非 0 → true（读回整块时按首字节判断） |
| SINT / USINT / BYTE         | 1    | 有符号 / 无符号               |
| INT / UINT / WORD           | 2    | LE                      |
| DINT / UDINT / DWORD / TIME | 4    | LE                      |
| REAL                        | 4    | float LE                |
| LREAL                       | 8    | double LE               |
| STRING                      | n    | 到首个 `\0` 为止             |
| WSTRING                     | 2n   | UTF-16LE 到 `\0\0`       |
| ARRAY                       | n×元素 | 按元素步长切分                 |
| 结构体                         | 按布局  | 按成员偏移切分（见第 7 节）         |

> **元素步长 ≠ 元素类型尺寸**。CODESYS 数组元素按对齐补位  
> （例：`ST_AXIS_CONTROL` 261B → 元素实际占 264B；`ST_AXIS_PARAM` 93B → 96B）。  
> 正确算法：`步长 = 数组总字节数 ÷ 元素个数`。

## 7. 结构体偏移：两条路径

### 7.1 布局可信（XML 给了 size 与每个成员 byteoffset）

直接整符号读一次，本地按偏移切分：

```
读 Application.GVL.aAxisCtl  →  2904B blob
元素步长 = 2904 / 11 = 264
成员偏移 = 元素序号 × 264 + 成员声明偏移
```

优点：**一次报文取回全部成员**。

### 7.2 布局可疑（UNION / size=0 / 成员偏移缺失或重叠）

XML 不给可信布局时，不能盲猜。流程：

```
① 逐名读每个叶子 → 得到「基准值」（真实可靠）
② 整符号读一次   → 得到 blob
③ 对账：用候选偏移在 blob 里切出值，与基准逐一比对
   · 步长 = blob 长度 ÷ 元素数（不整除直接失败）
   · 可疑成员：按类型对齐枚举候选偏移（IEC 推算位优先）
   · 某成员族在**所有元素**上都与基准一致 → 采纳该偏移
④ 全叶一致 → 缓存到 out/<APP>/drill-layout.json
   任一不符 → 放弃整读，继续用逐名读（慢但正确）
```

**判定「可疑」的规则**

- 类型 `size = 0`（UNION 特征）
- 任一成员 `byteoffset < 0` 或声明位置与前方成员冲突（重叠/回退）
- 递归：成员类型可疑则本类型可疑

**缓存失效条件**：整读字节数与缓存记录不一致（PLC 程序重编译 / 布局变化）→ 自动作废重学。

## 8. 错误码

| 位置                | 现象     | 常见原因                   |
| ----------------- | ------ | ---------------------- |
| 无响应               | 读帧超时   | 连接名额被占 / IP 不通 / PLC 忙 |
| 通道 `84 00`        | 通道错误   | 块序号或 CRC 错             |
| 服务 `14 02 02 09`  | 名字列表无效 | 设备令牌用了 0               |
| 服务 `20 02 02 00`  | 读取被拒   | 类型含指针/字符串等不可整读成员       |
| 写响应 `20 02 0F 00` | 写入被拒   | BOOL 用了 4 字节           |
| 写响应 `20 02 00 00` | 成功     | —                      |

客户端把这些翻译成中文原因，原始报文保留在控制台日志区。
